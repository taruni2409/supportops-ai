# NovaBank Support Escalation Policy

## 1. Standard Escalation

A support case should be escalated when the issue cannot be resolved using the
available support procedure or requires investigation by a specialist team.

The escalation should include a concise description of the problem, relevant
transaction information, troubleshooting already completed, and supporting
evidence supplied by the customer.

## 2. Urgent Security Escalation

Cases involving suspected fraud, account takeover, stolen cards, compromised
credentials, or unauthorised account access should receive urgent attention.

Support agents should first take any available action required to secure the
customer's account and then escalate the case to the Fraud and Security team.

## 3. Payment and Transfer Escalation

Payment and transfer cases should be escalated when the relevant policy
timeframe has passed and the issue remains unresolved.

Before escalation, agents should collect the transaction amount, transaction
date, merchant or recipient details, and any available supporting evidence.

The case should be routed to the specialist team responsible for the relevant
payment type.

## 4. Escalation Documentation

Every escalation should contain enough information for the receiving team to
continue the investigation without unnecessarily repeating work.

Support agents should record the customer's issue, actions already performed,
relevant dates and amounts, supporting evidence, and the reason for escalation.

Agents should not state that an investigation has been completed unless a
responsible specialist team has confirmed completion.
